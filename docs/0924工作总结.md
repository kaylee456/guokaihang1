### 四、API 端点

本期无前端，对外仅由顶层编排器调用，接口面收敛为三个（`fetch`/`resolve` 本期无消费方已移除，后续接入前端需 drill-down 再按需恢复）：

| 端点 | 输入 | 用途 |
|---|---|---|
| `GET /skill/customer_mgmt/query` | `?keyword=&org_id=` | **主入口**：参与人名称/客户编号 → 解析 CST_ID → 客户管理概览 |
| `GET /skill/customer_mgmt/manager_customer_count` | `?manager_oa=` | 按主责人工号统计当前负责客户数 |
| `POST /skill/customer_mgmt/main_manager/save` | `{cst_id, operator, fields}` | 保存经营主责人（按 CST_ID upsert：无记录=新增，已有=更新） |

#### 统一返回结构

```json
{ "status": "ok", "message": "", "data": ..., "resolved": {...} }
```

`status` 取值：`ok` / `not_found` / `multiple` / `empty_input` / `invalid_input` / `error`。

#### query 唯一命中返回

```json
{
  "status": "ok",
  "resolved": { "cst_id": "...", "org_id": "...", "cst_fullnm": "...", "multi_tenancy_id": "..." },
  "data": {
    "customer": { ... },
    "supply_rela": { "RELA_ID": "...", "SUPPLY_RELA": "...", "DETAIL_ID": "..." },
    "supply_rela_details": [ { "DETAIL_ID": "...", "SCORE": "...", ... } ],
    "main_manager": { "CST_ID": "...", "MAIN_MANAGER_NAME": "...", "MANAGER_ROLE": "..." }
  }
}
```

## 2026-09-24　接口统一与财务 Skill 调整

### 一、背景

三大业务 skill（财务 financial / 客户业务 customer_business / 客户管理 customer_mgmt）输出模式此前不完全统一：financial 缺 `status`/`message`（仅用 `answer` 兜底），另两类已对齐 `{status, message, data}` 信封。本次统一 financial 并沉淀接口规范。

### 二、改动清单

| 文件 | 内容 |
|---|---|
| `backend/app.py`（改） | `POST /skill/financial/ask` → `POST /skill/financial/query`；异常兜底改 `resp.error(exc)` |
| `backend/skills/financial_qa.py`（改） | `ask()` 复用 `backend/common/response` 信封，返回 `{status, message, data, resolved, period, answer, extracted}`；`answer` 全路径恒存在 |
| `start.sh`（改） | 启动提示同步新路径 |
| `docs/接口规范.md`（新增） | 统一信封 / status 枚举 / 开发规则 / 三类 skill 端点与字段明细 |

### 三、接口规范要点

- 统一信封：`{status, message, data, resolved, candidates, answer, extracted, error}`
- status 枚举：`ok / not_found / multiple / empty_input / invalid_input / no_business_data / error`
- 自然语言入口 `/query`：`answer` 恒存在；确定性入口 `/fetch`：无 `answer`
- 信封由 `backend/common/response.py` 单点产出，业务层禁止手写

### 四、遗留

- `GET /skill/financial/indicators`、`GET /skill/customer_business/resolve` 仍为旧信封 `{ok, ...}`，属直取端点，本次未迁移。
