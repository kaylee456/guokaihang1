# Skill 接口规范

> 适用范围：三大业务 skill —— 财务（financial）、客户业务信息（customer_business）、客户管理情况（customer_mgmt）。
> 目标：统一返回信封与状态码，前端按 `status` 统一分派；后续新增 skill 一律遵循本规范。
> 单一事实来源：信封由 `backend/common/response.py` 产出，禁止在业务层手写信封。

---

## 一、统一返回信封

所有 skill 主入口（自然语言 `/query` 与确定性 `/fetch`）统一返回：

```json
{
  "status": "ok",
  "message": "",
  "data": [],
  "resolved": {},
  "candidates": [],
  "answer": "",
  "extracted": {},
  "error": ""
}
```

| 字段 | 是否必填 | 说明 |
|---|---|---|
| `status` | 必填 | 状态码，取值见第二节 |
| `message` | 必填 | 人类可读提示；`ok` 时可为空串 |
| `data` | 必填 | 业务数据（list / dict）；非 `ok` 时恒为 `[]` |
| `resolved` | 可选 | 唯一命中客户时的解析结果 |
| `candidates` | 可选 | `multiple` 时全部候选，不自行过滤 |
| `answer` | 自然语言入口恒存在 | LLM 合成的中文回答；非 `ok` 时等于 `message` |
| `extracted` | 自然语言入口恒存在 | LLM 抽参原文，调试用 |
| `error` | 仅 `error` 时 | 原始异常字符串 |

---

## 二、status 枚举

| status | 含义 | 使用方 |
|---|---|---|
| `ok` | 成功，`data` 有效 | 全部 |
| `not_found` | 未匹配到对应记录 | 全部 |
| `multiple` | 多命中，需上层澄清（候选在 `candidates`） | 全部 |
| `empty_input` | 入参为空 | 全部 |
| `invalid_input` | 入参非法（缺必填、客户不存在等） | customer_business / customer_mgmt |
| `no_business_data` | 命中客户但无业务数据 | 仅 customer_business |
| `error` | 执行异常（端点 try/except 兜底） | 全部 |

---

## 三、通用规则（后续开发必须遵守）

1. **信封单点产出**：一律复用 `backend/common/response.py` 的 `ok / fail / not_found / multiple / empty_input / invalid_input / error`，不得在业务层手写 `status/message/data`。
2. **`data` 恒为集合**：成功时是 list 或 dict，非成功时恒为 `[]`。
3. **`answer` 恒存在**（仅自然语言入口）：`ok` 时是 LLM 合成回答，非 `ok` 时直接取 `message`，前端无需判空。
4. **确定性入口不给 `answer`**：`/fetch`、GET 直取只给结构化 `data`。
5. **`resolved` 字段名随源表而异**，但统一放在 `resolved` 键下（见第四节各表）。
6. **端点兜底**：每个端点 try/except 统一 `resp.error(exc)`，不裸抛 500。
7. **多命中不猜**：返回 `multiple` + 全部 `candidates`，由上层澄清。

## 四、各 skill 端点与字段

### 4.1 financial（财务信息）

| 端点 | 方法 | 说明 | 返回 status |
|---|---|---|---|
| `/skill/financial/query` | POST | 自然语言主入口（走 LLM） | `ok` / `not_found` / `multiple` / `error` |
| `/skill/financial/indicators` | GET | 免 LLM 直取 | ⚠️ 旧信封 `{ok,msg,...}`，待统一 |

- `resolved` 字段：`id`、`customer_code`、`customer_name`、`customer_type`、`industry_type`、`credit_rating`、`listed`
- 额外字段：`period`（`{year, cycle, period_no}`）、`answer`、`extracted`

### 4.2 customer_business（客户业务信息）

| 端点 | 方法 | 说明 | 返回 status |
|---|---|---|---|
| `/skill/customer_business/query` | POST | 自然语言主入口（走 LLM） | `empty_input` / `not_found` / `multiple` / `no_business_data` / `ok` / `error` |
| `/skill/customer_business/fetch` | POST | 确定性直取 | 同上（无 `answer`） |
| `/skill/customer_business/resolve` | GET | 仅客户解析 | ⚠️ 旧信封 `{ok,count,candidates}`，待统一 |

- `resolved` 字段：`cst_id`、`org_id`、`cst_nm`
- 额外字段：`matched_tables`（命中的来源表名）、`answer`、`extracted`

### 4.3 customer_mgmt（客户管理情况）

| 端点 | 方法 | 说明 | 返回 status |
|---|---|---|---|
| `/skill/customer_mgmt/query` | POST | 自然语言主入口（走 LLM） | `empty_input` / `not_found` / `multiple` / `ok` / `error` |
| `/skill/customer_mgmt/fetch` | POST | 确定性直取 | 同上（无 `answer`） |
| `/skill/customer_mgmt/manager_customer_count` | GET | 按主责人工号统计负责客户数 | `invalid_input` / `ok` / `error` |
| `/skill/customer_mgmt/main_manager/save` | POST | 保存经营主责人（按 `CST_ID` upsert） | `invalid_input` / `ok` / `error` |

- `resolved` 字段：`cst_id`、`org_id`、`cst_fullnm`、`multi_tenancy_id`
- 保存返回 `data`：`{cst_id, affected}`，额外字段 `action`（`insert` / `update`）

## 五、返回示例

### 自然语言入口命中（ok）

```json
{
  "status": "ok",
  "message": "",
  "data": [ { "indicator_name": "营业收入", "category_name": "规模指标", "indicator_value": 123.4, "display_unit": "万元" } ],
  "resolved": { "id": 1, "customer_code": "MOCK0001", "customer_name": "西安正和科技" },
  "period": { "year": 2026, "cycle": "semiannual", "period_no": 1 },
  "answer": "该客户 2026 年半年度营业收入为 123.4 万元……",
  "extracted": { "customer": "西安正和科技" }
}
```

### 多命中（multiple）

```json
{
  "status": "multiple",
  "message": "匹配到 2 个客户，请确认具体是哪一个。",
  "data": [],
  "candidates": [ { "cst_id": "1001", "org_id": "M001", "cst_nm": "新能源A股份公司" }, { "cst_id": "1002", "org_id": "M002", "cst_nm": "新能源B股份公司" } ],
  "answer": "匹配到 2 个客户，请确认具体是哪一个。",
  "extracted": { "name_or_id": "新能源" }
}
```

### 异常（error）

```json
{
  "status": "error",
  "message": "查询出错：[CODE:-2111]...",
  "data": [],
  "error": "[CODE:-2111]..."
}
```
